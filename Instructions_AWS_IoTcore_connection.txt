Need to do four things in AWS IoT Core, in London (eu-west-2) or whichever region is being used:

Create a thing named kobra2neo, and auto-generate a certificate for it. Download the device certificate, the private key and AmazonRootCA1.pem into a certs folder next to the script. They’re only offered for download once, at creation.
Attach a policy to that certificate allowing exactly what the gateway does:
json
   {
     "Version": "2012-10-17",
     "Statement": [
       {"Effect": "Allow", "Action": "iot:Connect",
        "Resource": "arn:aws:iot:eu-west-2:<ACCOUNT_ID>:client/kobra2neo-pc-gateway"},
       {"Effect": "Allow", "Action": ["iot:Publish", "iot:RetainPublish"],
        "Resource": ["arn:aws:iot:eu-west-2:<ACCOUNT_ID>:topic/printer/kobra/telemetry",
                     "arn:aws:iot:eu-west-2:<ACCOUNT_ID>:topic/printer/kobra/status"]}
     ]
   }

iot:RetainPublish is needed because the online/offline status is retained. Without it, IoT Core drops the connection.
3. Copy the endpoint from IoT Core → Settings (xxxx-ats.iot.eu-west-2.amazonaws.com) into aws.endpoint in gateway_config.json. Rename the certificate files to match the config, or change the paths in the config.
4. Watch the data arrive in the IoT Core MQTT test client by subscribing to printer/kobra/#, before she builds anything else.

Then run python printer_gateway_v1.py without --dry-run. In the log you should see “Connected to AWS IoT Core”, followed by messages appearing in her test client every 2 s.

A good check of the buffering is to unplug your network for a minute while it’s running. The queued= count in the log rises, then drains when the connection returns, and the seq numbers in her test client stay continuous.
